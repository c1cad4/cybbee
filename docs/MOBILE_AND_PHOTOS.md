# Мобильный интерфейс, поиск и приватные фото

Создатель приложения указан в интерфейсе: CicadaFarm. Подпись переводится вместе с интерфейсом, название сохраняется.

На ширине до 760 px меню становится компактной горизонтальной полосой; формы используют шрифт 16 px, кнопки имеют высоту от 44 px, диалоги ограничены высотой экрана. Browser QA выполнен при viewport 390×844. Это не проверка физических телефонов. Ссылки, поля ввода и пользовательские записи сохраняют свои исходные значения.

32 дополнительные строки основных действий переведены на ru/en/zh/hi/es/ar/pt/bn/fr/de. Подробные статьи, большая часть пояснений и динамические ошибки всё ещё русские. Нельзя считать это завершённой локализацией всего приложения.

Поиск по журналу на странице пасеки использует текст, название улья, препарат, метод, страну, тип события и включительные границы дат. Результаты выводятся порциями по 20. Старые осмотры без kind считаются осмотрами, а данные пользователя экранируются.

## Облачные фото
Хранилище R2 BUCKET используется только сервером. Таблица bee_photos связывает снимок с владельцем и ID осмотра. API /api/photos проверяет Sites identity для каждого чтения и записи. Получение фото требует совпадения владельца в D1; публичных прямых URL не выдаётся. Ответы запрещают кеширование. Это контроль доступа, а не сквозное шифрование от оператора хостинга.

Пользователь сначала синхронизирует журнал, затем явно разрешает отдельный обмен фото. JPEG до 500 КБ передаётся JSON/base64; модель и координаты к запросу не добавляются. Максимум 100 фото/аккаунт и 3/осмотр. Клиент загружает или восстанавливает до 10 фото за действие и показывает остаток. Повторный ID не перезаписывается. Восстановление требует наличия соответствующего осмотра на устройстве.

Атомарная SQL-резервация учитывает незавершённые загрузки в квоте; после R2 put запись становится доступной. При обычной ошибке запись и объект очищаются. D1 и R2 не имеют общей транзакции: аварийное завершение процесса между шагами может оставить pending-запись или объект; автоматическая сверка и экран удаления ещё не реализованы. Локальные JSON-копии остаются независимым резервом.

SQLite + mock R2 тесты проверяют согласие, принадлежность журналу, изоляцию владельцев, повторную загрузку и квоту на осмотр. Локальный browser QA использует синтетическое фото и mock bucket; настоящие фото пользователя не загружались. Проверка реального восстановления с другого физического устройства ещё предстоит.

Фоновые push при полностью закрытом приложении не внедрены. Текущие уведомления открытого приложения и ICS сохраняются. Требуется отдельный канал Web Push, управление подписками/секретами и проверенный планировщик; расписание Codex само по себе не является службой доставки всем пользователям.
